# LeetCode Practice

This repository contains my solutions to LeetCode problems, written primarily in **C#**.

The goal is not only to collect accepted solutions. I want to improve how I approach unfamiliar problems, recognise reusable patterns, write clearer code, and understand the trade-offs behind algorithmic choices.

## Goals

- Build a consistent record of completed LeetCode problems.
- Improve problem-solving and algorithmic thinking through practice.
- Learn reusable techniques and recognise when they apply.
- Review time and space complexity, code clarity, and possible improvements.
- Keep a record of lessons so that progress builds from one problem to the next.

## How I Practise

I try to solve each problem independently before asking for help. Once I have an attempt, I may use AI assistants such as **ChatGPT** and **Claude** to:

- Review my approach and identify correctness issues or edge cases.
- Explain concepts, patterns, and language features I do not understand.
- Discuss time and space complexity and compare alternative approaches.
- Improve code clarity without adding unnecessary complexity.
- Help me understand *why* an approach works so I can apply it to future problems.

AI assistance is part of the learning process, not a substitute for it. I aim to understand the reasoning, make changes myself, and be able to explain the solution rather than simply copy an accepted implementation.

## Repository Contents

- **Problem solutions:** C# implementations of LeetCode problems.
- **[`LeetCode-Learnings.md`](LeetCode-Learnings.md):** Notes on problem-solving patterns, lessons from my attempts, code-quality improvements, and complexity analysis.

The learning notes are updated in batches of **10 completed problems** so that each batch can be reviewed and committed together. Problems I have not yet understood or completed independently remain marked as in progress.

## Approach to Improvement

My preferred workflow is:

1. Understand the problem and its constraints.
2. Attempt a solution independently.
3. Test it against examples and edge cases.
4. Get feedback on correctness, clarity, complexity, and alternatives.
5. Make sure I understand the reasoning and can reproduce the solution.
6. Record the reusable lessons.

The priority is steady improvement and understanding, not just the number of accepted submissions.
